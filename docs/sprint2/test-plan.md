## 1\. Продукт і межі тестування

«СтейНау» — односторінковий вебзастосунок (React) для бронювання номерів готелю. Охоплює:

- **Гостьову частину**: перегляд готелю і номерів, перевірка доступності, бронювання, контактна форма.  
- **Адмінпанель**: вхід, керування номерами, повідомлення гостей, звіт заповнюваності.  
- **Модуль бізнес-логіки** (Java 17, пакет `ua.kpi.tzyapz.staynow`): валідація бронювань, сезонні тарифи, надбавки за вихідні, політика скасування, перевірка зайнятості номерів.

**Demo-застосунок:** [https\://automationintesting.online](https://automationintesting.online)  
**Адмінпанель:** [https\://automationintesting.online/admin](https://automationintesting.online/admin) (admin / password)

**Поза обсягом тестування:** онлайн-оплата, мобільні застосунки, масштабування production-інфраструктури.

**Обмеження demo:** дані (номери, бронювання, повідомлення) скидаються до початкового стану періодично; ціни показуються у фунтах (£), у модулі — у гривнях (UAH). Навантажувальне тестування та атаки (ін'єкції, XSS тощо) на публічному demo заборонені (каталог, розд. 1.3) — виконуються лише на локальному резерві.

### 4\. Незастосовні типи тестування

| Тип | Обґрунтування незастосовності |
| :---- | :---- |
| **Інсталяційне** | «СтейНау» — вебсервіс (SaaS): гість і адміністратор нічого не встановлюють; Maven-збірка модуля — процедура розробки, а не інсталяція продукту. |
| **Доступності (availability)** | SRS не задає вимог до резервування або безперервної роботи (немає вимоги типу «система відновлюється за N хв»); механізми гарячої заміни або дублювання поза обсягом специфікації — немає критерію «пройдено». |
| **Локалізації** | Інтерфейс demo існує лише в англійській мові; SRS не передбачає локалізованих версій. Javadoc українською (D-10) — документація коду, а не локалізація продукту. |
| **Стресове** | SRS не задає граничної ємності або поведінки при перевантаженні — немає критерію «пройдено». Додатково: навмисне перевантаження публічного demo до відмови заборонене (каталог, розд. 1.3) і порушить роботу інших команд. |
| **Стрибкове (spike)** | SRS не містить вимог до поведінки при раптових стрибках навантаження — немає критерію «пройдено». Виконання на публічному demo неприйнятне через спільне середовище. |
| **Стабільності** | SRS не задає вимог до тривалої безперервної роботи (немає «система працює стабільно N годин») — немає критерію «пройдено». Demo скидається самостійно — тривала (72+ год) сесія без скидання неможлива. |
| **Вузьких місць (bottleneck)** | Bottleneck-аналіз вимагає доступу до серверних метрик і трасування між компонентами; до серверної частини demo доступу немає. SRS не задає вимог до пропускної здатності окремих компонентів Java-сервісів (каталог, розд. 6.1). |
| **Витоків пам'яті** | Аналіз витоків пам'яті серверної частини demo неможливий через відсутність доступу до JVM process. Клас `Availability` зберігає стан між викликами в рамках однієї JVM-сесії (BL-70), але між тестами стан скидається разом із JVM — витік між тестами неможливий. |
