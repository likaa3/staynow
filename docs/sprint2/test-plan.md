## 1\. Продукт і межі тестування

«СтейНау» \- односторінковий вебзастосунок (React) для бронювання номерів готелю. Охоплює:

- **Гостьову частину**: перегляд готелю і номерів, перевірка доступності, бронювання, контактна форма.  
- **Адмінпанель**: вхід, керування номерами, повідомлення гостей, звіт заповнюваності.  
- **Модуль бізнес-логіки** (Java 17, пакет `ua.kpi.tzyapz.staynow`): валідація бронювань, сезонні тарифи, надбавки за вихідні, політика скасування, перевірка зайнятості номерів.

**Demo-застосунок:** [https\://automationintesting.online](https://automationintesting.online)  
**Адмінпанель:** [https\://automationintesting.online/admin](https://automationintesting.online/admin) (admin / password)

**Поза обсягом тестування:** онлайн-оплата, мобільні застосунки, масштабування production-інфраструктури.

**Обмеження demo:** дані (номери, бронювання, повідомлення) скидаються до початкового стану періодично; ціни показуються у фунтах (£), у модулі \- у гривнях (UAH).

| **Доступності (availability)** | Demo запущений на одному сервері без резервування і балансування навантаження; механізми гарячої заміни або дублювання для demo не передбачені і виходять за межі обсягу тестування. |
| **Локалізації** | Інтерфейс demo існує лише в англійській мові; локалізованих версій не передбачено специфікацією. Модуль BL пишеться українською лише у javadoc, але це не l10n продукту. |
| **Стресове** | Demo \- спільне середовище для всіх команд; навмисне перевантаження до відмови може порушити роботу інших команд. Стресові ліміти не визначені специфікацією (P-20 абстрактна, є дефектом). |
| **Стрибкове (spike)** | Продукт не має задокументованих вимог до поведінки при раптових стрибках навантаження; spike-тестування на demo неприйнятне через спільне середовище. |
| **Профілювання** | Базових показників для порівняння немає (версія 1 \- перша); профілювання доцільне з версії 2, коли є еталон з v1. |
| **Стабільності** | Demo скидається до початкового стану самостійно; тривала (72+ год) безперервна робота без скидання неможлива в умовах demo-середовища. |
| **Вузьких місць (bottleneck)** | Demo-застосунок \- проста SPA без мікросервісної архітектури; доступ до серверних метрик і діаграм передавання даних відсутній. Bottleneck-аналіз вимагає інструментів, недоступних для demo. |
| **Витоків пам'яті** | Модуль BL-10…BL-80 не має стану між викликами (stateless); об'єкти `BigDecimal` і `LocalDate` не зберігаються між тестами. Виток пам'яті можливий лише при тривалій роботі серверної частини demo, до якої немає доступу. |
